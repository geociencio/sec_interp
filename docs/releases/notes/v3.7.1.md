# SecInterp v3.7.1: Security Patch

We are announcing the release of **SecInterp v3.7.1**, a patch that hardens the settings persistence layer and closes a gap in our release security pipeline.

## 🔒 Key Changes

### Silent Exception Swallow Fixed
A defensive fallback in the settings persistence (`_get_setting`) was silently swallowing all exceptions with `try/except/pass`. If the configuration service failed to read a key — due to a bug, malformed data, or an unexpected error — the failure disappeared without a trace, and the user had no visibility into why their settings were not restored.

The offending block now logs a warning with the failed key and error message, while preserving the graceful fallback to the default value. This resolves the Bandit `B110` (try/except/pass) finding flagged by our security scanner.

### Release Pipeline Hardened
We wired the full security scan (Bandit + detect-secrets + Flake8) into the release workflow. Every future release now runs Bandit's complete rule set — including `try/except/pass`, hardcoded passwords, and unsafe function detection — before packaging, preventing code smells like this one from reaching distribution.

## 📈 Quality & Reliability
This release passes **620+ automated tests** via Docker. All project functions comply with the **Cyclomatic Complexity ≤ 10** gate, and the security scan reports **0 vulnerabilities** with a **100/100** score.
