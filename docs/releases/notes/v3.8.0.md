# SecInterp v3.8.0: Core/GUI Decoupling & Reliability

We are announcing **SecInterp v3.8.0**, a release that hardens the plugin's internal
architecture and ships two targeted reliability fixes on top of the Qt6 / QGIS 4
compatibility work.

## 🏗️ Architecture: Core/GUI Decoupling

SecInterp now enforces a strict **Extract-then-Compute** boundary between QGIS-facing code
and business logic:

- Business services (`StructureService`, `GeologyService`, `ProfileService`, the drillhole
  domain, and the validation layer) were migrated to a **QGIS-agnostic core**.
- All QGIS interaction — feature reading, buffering, raster sampling, and layer resolution —
  now lives in a dedicated `gui/adapters/` layer.
- Decimation, polyline metrics, line azimuth, projection, and densification were
  reimplemented in **pure standard-library math**.
- A new **architecture allowlist gate** prevents regressions and drove the migration from
  **36 down to 6** coupled `core/` modules.

This refactor has **no user-facing behavior change**; it makes the plugin easier to test,
safer to run in background tasks, and cheaper to maintain.

## 🔧 Reliability & Compatibility

- **QGIS 4 Legend Fix**: The legend widget now uses the scoped `QEvent.Type.Resize` enum,
  resolving a runtime `AttributeError` on QGIS 4.
- **3D Interpretation Export**: Enabled by default, so 3D interpretation output is available
  without extra configuration.

## 🧰 Tooling

- Quality gates are now driven natively by `qgis-plugin-analyzer` 1.14.0: the
  cyclomatic-complexity gate (`analyze --max-cc 10`) and the AST-based `MISSING_I18N` rule.
  The internal `check_cc.py` and `verify_i18n_hygiene.py` scripts were retired.

## 📈 Quality & Reliability

This release passes the full Docker test suite (**606 tests**), the **Cyclomatic Complexity
≤ 10** gate, the i18n AST gate, and the full security scan (Bandit + detect-secrets), with a
security score of **100/100**. Docstring coverage is **100%**.
